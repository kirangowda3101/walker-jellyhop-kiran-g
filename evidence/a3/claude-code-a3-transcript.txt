  2. The check: godot/tests/test_a3_assets.gd

  It follows the conventions in test_slice.gd:
  - extends SceneTree.
  - A check(id, passed, observed) function that prints one JSON line per check
    with PASS or FAIL.
  - A JSON report written to evidence/a3-assets-<unix time>.json.
  - A summary line, A3 ASSET CHECKS: N checks / F failures.
  - quit(1 if failures else 0).
  
  Every length is compared with a tolerance of 0.001 m (1 mm). Expected values
  are constants taken from the brief (the table above), never read from the
  files being checked.

  Part A: each .glb on its own (the file is loaded and instanced, not placed in
  the scene)

  1. Load. load() returns a PackedScene that instances without errors.
  2. Node transforms. Print each node's name, type, scale and rotation. FAIL
     rotation is how a sideways import would show up (predicted failure case 1).
  3. Bounding-box size. Built from the mesh vertices relative to the asset's
     root. Print the size and FAIL unless X, Y and Z match the brief.
  4. Which axis it stands along. Print the longest axis, for information only:
     for the platform it will be X, not Y. The check that counts is that the
     brief's height is on Y.
  5. Lowest and highest Y. FAIL unless the lowest is about 0 and the highest is
     about the brief height. An upside-down fork would show Y −1.5 → 0 here. 
  6. Shape orientation, from the vertices, to catch anything flipped:
     - Fork: width near the bottom (Y < 0.1) is about 0.5 (the prongs), and
       width near the top (Y > 1.4) is about 0.1 (the handle). 
     - Dome: width at the bottom is about 1.0 (base), and width near the top (Y
       > 0.7) is at most 0.24 (cherry).
     - Platform: the top face at Y = 0.25 spans the full 2.0 × 1.5.
  7. Triangle count. Counted from the mesh's main surfaces; Godot's automatic
     simpler versions for distance (LODs) aren't counted. FAIL if over budget,
     and print it next to the Blender count.
  8. Materials. Print each surface's material name, for information only.

  Part B: the scene
  1. Floor top is at Y = 0. Taken from the Floor node's own mesh bounds and its
     global transform, and compared with the constant 0.
  2. Each asset sits on the floor. The lowest point of each asset's vertices, in
     world coordinates, must be within 1 mm of the floor's top. The two values
     come from different nodes: the asset's vertices and the Floor mesh. Neither
     the asset's own position nor anything inside the asset is used as the
     reference.
  3. Instance scale. Each instance's scale is (1, 1, 1).
  4. JellyScaleRef. It measures 0.5 m on each side, its bottom is on the floor,
     and its box is at least 0.5 m from every asset's box.
  5. Camera framing. All 8 corners of each asset's box and of the reference cube
     are inside the camera's view (is_position_in_frustum).

  What the check does NOT prove

  - Not a playtest, and not a look at the screen. It checks numbers. It doesn't
    render, so it says nothing about colours, lighting, shadows, or whether the
    shot looks good.
  - "In view" only means geometrically inside the camera's view. Something could
    be in front of an asset, or an asset could look tiny, and the check would
    still pass.
  - It doesn't put the assets in the game. The game is 2D, the brief's planned
    placements are still open items, and there are no colliders, so nothing here
    tests the jelly landing on the platform or touching the fork.
  - "On the floor" only means on this scene's floor, which I'm building myself.
    It shows that the origins are consistent, not that the assets would line up
    in another scene.
  - Small errors pass. Anything under 1 mm passes, including the fork's 2.98e-08
    m.
  - It only tests the files as currently imported, with the current import 
    settings. It doesn't check the export settings or Blender itself.

  How I'll run it

  From the repository root:

  set -o pipefail
  timeout 120 godot --headless --path godot --script 
  res://tests/test_a3_assets.gd --fixed-fps 60 2>&1 | tee 
  evidence/a3-assets-run.log
  echo "exit: $?"

  - What each flag does:
    - timeout 120 stops Godot if it hangs for more than 2 minutes.
    - --headless runs without a window.
    - --path godot points at the project.
    - --script runs the check instead of the game.
    - --fixed-fps 60 steps the game at a fixed rate.
  - tee saves the output to a log while still showing it. pipefail makes sure
    Godot's exit code isn't lost behind tee, so nothing like | tail hides a
    failure.
  - I'll only call it a pass if all three hold:
    - the exit code is 0;
    - the summary line shows 0 failures;
    - there's no SCRIPT ERROR or ERROR in the log.

    I'm not sure Godot returns a nonzero exit code when a script fails to load,
    so the summary line has to be there too.
  - If the .glb files change later, run godot --headless --path godot --import
    first, so the check doesn't read an out-of-date import.
